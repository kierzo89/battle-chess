# Typed asset data and actual reader execution

Ten new C DATA definitions reproduce 132 initialized bytes in the expanded
image: four metadata counts, the file handle, file-kind flag, two filenames,
three disk/open messages, a seek error and an overflow message. Every definition
is independently compiled by pinned MSC5.00 `/AS /Zl /Zi` before reference
comparison. Complete DATA SEGDEF and public boundaries are required, with no
holes, fixups or other nondebug allocations. REA MCP confirms each complete
original byte range, including string terminators.

The proof is `evidence/asset-initialized-data-experiment.json`; reproduce it
with `python3 matching/evidence/asset-initialized-data-probe.py`. All ten
definitions are canonical in `config/units.json` and share actual symbols with
their reconstructed consumers. This proves individual initialized contributions;
the final source module ownership and whole-program placement remain unresolved.
These expanded DATA bytes receive no physical packed-file coverage.

`evidence/asset-read-link-probe.py` independently compiles the real two-byte
`asset_file = -1` definition, real 128-byte asset reader and an explicit synthetic
test harness. Authentic pinned LINK3.65 and SLIBC produce a runnable DOS image.
The complete consumer bytes are independently relocated to actual map addresses
and checked against the emitted executable, including the real handle reference.
The map contains exactly one handle definition and its initializer remains FFFF.

The executable successfully reads 1,234 generated bytes in three chunks into a
70,000-byte harness array starting at offset65,000. It checks all destination
bytes and both adjacent guards across the offset65,535/65,536 boundary. The
fixture and harness are test inputs only; they establish no game allocation or
additional matching credit. No original executable or reference bytes are read
or mounted by this link/execution control. Full provenance, map, fixups, fixture
and executable hashes are retained in `evidence/asset-read-link-experiment.json`;
the generated executable and logs are under `build/asset-read-link/`.
