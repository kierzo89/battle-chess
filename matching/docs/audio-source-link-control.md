# Target-free audio-adapter LINK and execution control

Both authentic LINK3.65 object orders successfully link and execute unchanged `src/audio_assets_flow_match.c`, containing the complete188/172-byte adapters. Each complete360-byte CODE contribution is independently relocated from its actual object using actual MAP symbol placements, then equals its emitted EXE interval byte for byte. All27 CODE fields are owned and reapplied. Both actual/emitted source MZ sets contain exactly the two far-callback segment words.

The recording callbacks compile separately under C5 medium model and occupy a real nonzero CODE segment (actual MAP01F1:000A /0039 in the final controls). The typed far interface carries a32-bit frequency,16-bit length and32-bit huge cursor. Seven executed callback assertions verify full frequency values, kind, length and pointer identity; disabled mode runs both adapters without a callback or header access. The unused incoming channel word varies across cases.

SLIBC alone fails with genuine unresolved `__aNNaldiv`, `__aNlshl` and `__aNlmul` references. The final controls therefore use independently pinned original SLIBC plus LIBH, with no replacement helper bodies or symbol adapters. Actual MAP resolves all three arithmetic helpers and SLIBC's `__aNahdiff`; full library/tool hashes and the separate helper archive manifest are retained. The initial failure log remains in `build/audio-authentic-link/AUDIO-HARNESS-CALLS/SLIBC-only-failure.LOG`.

Executed cases cover positive, negative-divisor and truncating compound long division; pitch adjustment and zero clamping; both far callbacks; and a huge-pointer subtraction whose begin/end cross a64KiB boundary. The synthetic AssetCache type is10 bytes and its three-record array is a genuine30-byte near COMMON definition. A65,552-byte huge fixture supplies the boundary case, not original storage. Host-side raw observation checks do not rely only on matching C pointer expressions: the program logs both cache endpoint words and each recorded cursor's words. An independent DATA anchor supplies the actual DOS load paragraph; adding it to actual MAP fixture addresses reproduces every observed physical address. Boundary begin/end physical addresses differ by10, and the callback cursor equals the MAP fixture base plus65,536. Payload tags90/165 are also read back.

The first adapter forwards its first header word as length and reads the divisor at+2, forwarding samples at+4. The second forwards the whole end-minus-begin difference while its cursor is begin+2. This control verifies those observed arguments without inventing the intended driver length units or reading a device sample span. Recording callbacks do not produce real audio. Negative pitch checks describe actual emitted C5 signed-shift behavior, not a portable ISO C claim. Zero divisors, arbitrary lengths and device timing remain outside this bounded control.

Primary proof/reproducer: `evidence/audio-authentic-link-experiment.json` / `evidence/audio-authentic-link-probe.py`. Actual objects, both EXEs/MAPs, build scripts and complete LINK/run logs are retained under `build/audio-authentic-link/`. Harness-only sources are `src/probes/audio-link/harness.c` and `calls.c`. Every generation drive contains only new source-built objects and build script, plus a read-only tool drive with pinned LINK, SLIBC and LIBH. No original game executable, carrier, placement manifest or target-address binding is read or mounted during generation. All bindings come from each actual MAP.

Zero additional matching, runtime or original-storage credit. Canonical source, registry, core and tests remain unchanged. This establishes a useful real-runtime/far-callback ABI control; it does not establish a full-game source-link manifest or executable match.
