# Authentic Microsoft LINK backend for LIBH helpers

The dedicated `msc500-authentic-link` backend rebuilds three complete arithmetic
helpers from independently pinned MSC5.00 LIBH objects using authentic Microsoft
LINK3.65. It handles the library's overlapping LEDATA through the original
linker, while keeping the strict C object parser unchanged. The initial helpers
are multiplication at F32E (52 bytes), left shift at F362 (11 bytes), and signed
right shift at F36E (11 bytes): **74 runtime-library bytes, zero C/ASM credit**.
Canonical registration and current totals come from the generated checker report.

## Independent inputs and setup

[config/runtime_libh.json](../config/runtime_libh.json) pins the whole LIBH file,
the PCjs installation disk, the exact member offsets/hashes and the independently
declared code lengths. The library hash is
`768bfe171ebcad6d44aeca830ec8d19b31f02ce84ab35c81fc48fcf3f1e14858`.
The archive path `/LIB/LIBH.LIB` is traversed through FAT12 directories; sectors,
chain bounds, loops, duplicate entries, file types and lengths are checked.
The complete archive is checked before extraction and the library before a
staged installation is published. Existing installations require an exact
manifest and whole-library pin match.

```sh
python3 matching/setup_toolchain.py --compiler msc510
python3 matching/setup_libh.py
# Offline alternative using the preserved, hash-pinned disk:
python3 matching/setup_libh.py --archive matching/build/probes/MSC500-DISK4.json
python3 matching/check.py
python3 -m unittest discover -s matching/tests -p test_runtime_libh.py -v
```

The checker does not download these inputs. `setup_libh.py` installs only the
independent library; the existing official tools installer supplies LINK. The
compiler profile is named MSC5.10, while its actual LINK tool is version3.65,
SHA-256 `124a3c800edc16b60f696d35a9dfec798b68b78fe2ca90c5988ea76bdeab1a8a`.
Its repository and commit are the existing pinned official MS-DOS tools profile.
The archive's proprietary license classification remains separate from the
independently released official tool's license.

## Backend contract and isolation

`runtime_libh.load_member(member_id, project)` returns the pinned configuration,
selected profile, unchanged extracted member and a narrow independent layout.
`runtime_libh.link_member(member_id, project, dosbox, timeout)` returns a
`RuntimeLinkResult` containing `image`, `object_bytes` and JSON-serializable
`provenance`. Initial member IDs are `near_lmul`, `near_lshl`, `near_lshr`.

The caller supplies no expected code bytes or reference executable. Every call
extracts from the newly hash-checked whole library and invokes LINK in a fresh
scratch directory. DOSBox mounts only a drive containing the unchanged member
and build script, plus a read-only drive containing the independently pinned
LINK executable. Neither the repository nor CHESS.EXE is mounted. There are no
cached generated bytes or stale output inputs. `/NOD` prevents unrelated default
libraries from being pulled into these helper probes.

The layout reader validates record lengths/checksums, declared segment bounds,
public definitions and complete initialized coverage. It records overlapping
LEDATA writes and their record locations but never merges writes or emits code
bytes. Authentic LINK alone interprets the unchanged object. Initially the
backend admits exactly one nonempty CODE segment, zero-length other segments,
no external declarations and no FIXUPP records. This keeps code placement
independent for the three small helpers. Other library forms fail explicitly.

`library16.extract_member` remains strict by default. Its keyword-only
`validate_object=False` option is used by this separately pinned authentic-LINK
path after container/member pin checks; it does not skip container record
checksum checks. The ordinary C path still uses the unchanged strict OMF reader
and still rejects overlapping code records.

## Exact output and provenance

The runner parses the complete MZ output, checks its physical/declaration bounds,
and requires the entire initialized image to equal the independently declared
CODE SEGDEF length. It checks the LINK map independently as well. It does not
trim to the target size, strip padding, mask fields or select a partial public
extent. Overlay bytes, extra initialized segments, incomplete images and any
emitted MZ relocation are rejected by this initial backend. The original MZ-site
sets for all three selected helpers are also empty.

The checker compares that full generated image with both retained complete REA
raw bytes and the pinned original interval. The member's public must be at the
start of the independently declared segment. The existing REA records identify
all 52/11/11 bytes; no function boundary is guessed from an early return or the
next symbol.

Provenance includes archive/library/member hashes, library offset, independent
layout and write overlaps, toolchain manifest and LINK hashes, official tool
repository/commit, command line, linker log/map, complete linked MZ/image hashes,
and all output MZ sites. The metadata explicitly assigns zero authored-C credit.
The earlier two-version linker comparison and raw member details remain in
[runtime-helper-libraries.md](runtime-helper-libraries.md).

Nine new tests cover actual full-byte/raw-REA/MZ comparisons for all three
helpers, repeated fresh isolated runs, unchanged strict C parsing, forged inputs,
explicit nested-directory installation, FAT chain failures, metadata boundaries,
and rejection of extra MZ bytes or relocation fields. The runner's initial
configuration is frozen at these three helpers. A bounded scan found only one
other near helper satisfying its pure-code/no-fixup policy, unsigned right shift;
that complete member does not match an original interval. The other near members
have external declarations and need a reviewed combined-link scope before they
can be admitted.
