574 independently generated bytes. [Full build evidence](../evidence/ui_next_build.json)
retains the five fresh source/object/tool hashes, complete CodeView3 procedure
extents, linked bytes and normal relocation arithmetic. Fresh original REA
dossiers establish each complete contiguous body. No bytes are patched,
truncated, masked or emitted by source macros/assembly.

These operation descriptions are static inferences from the retained instruction
flow, not claims of observed runtime execution or recovered historical names.
The mode fields' user-facing labels remain unresolved.

In91DC, a register temporary lives in an initial block, while the later loop
locals live in a separate block. The compiler therefore preserves SI around
the initial structure copy, reuses stack storage across the scopes, and uses
SI for the later loop, exactly as observed. This ordinary lifetime structure
explains the original sequence without inserted dummy operations.

In9371, the call to BB0E passes an eight-byte `Move` by value followed by1.
Passing five scalar arguments produced a different zero-argument optimization;
the aggregate source reproduces all four original memory pushes. The record
layout is supported by the initial/final structure copies and field accesses.

Both packed-mode helpers also match MSC5.00 `/AS /Gs /Zi` with no explicit
optimization option.91DC,9371 and93D6 differ with that bare-default setting;
`/Os` is retained in the proposal for all five.

The proposed canonical units are `build/ui-next-units.json`. Sources remain
ordinary standalone C and the registry/checker are unchanged by this worker.
