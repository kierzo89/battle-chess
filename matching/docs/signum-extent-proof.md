# Complete signum extent proof

The ordinary C sign function at image5C8B emits42 bytes with Microsoft C5.00
`/AS /Zi`. REA reports38 reachable bytes in three ranges. The four remaining
bytes are two unreachable short jumps at5C9E and5CAB; each jumps to the same
near epilogue as the preceding live return.

The new signed_signum_return_gaps_v1 profile in extent.py admits only the fixed
function identity, C5 backend/flags,42-byte CodeView extent and instruction
shape. It validates the actual near stack-probe fixup, six closed CFG blocks,
four distinct empty global xrefs, full raw42-byte equality and complete adjacent
147-byte raw context. The next body is authenticated by original SHA-256
88ce632ad439581e9c2a09990f16cb0ef52ab8e8d84234eef9fbf2c5859331e6.
Normal contiguous-body rules and all other exception profiles remain unchanged.

Independent review found that the first version authenticated only the adjacent
body's entry bytes. This did not permit incorrect sign-function credit, but was
weaker than the stated context guarantee. The validator now checks the full
next-body digest; a new test flips every mandatory adjacent byte and rejects it.

Fifteen targeted tests cover actual fresh C output, both dead jumps, every byte
mutated while raw/generated bytes agree, exact body/CFG/provenance, all four gap
xrefs, fresh extent/fixup ownership, and every next-body byte. An additional
Unicorn test executes the original code and real stack probe for every signed
16-bit input, comparing the return with host-compiled ordinary C.

The live pen source has three complete procedures /376 CODE bytes and31 fixups.
Its original odd start is still a full-link layout obligation. See
 evidence/pen_drawing_sign_match-contribution.json and tests/test_signum_extent.py.
